# cdymm.com 战略定位与发展规划

> 日期：2026-10-30
> 依据：本机 new-api 二开仓与 infinite-canvas 画布仓实证 + liblib / bitahub / zzai 三站逆向调研
> 性质：阶段性战略基线。数字与时间为估算，随执行滚动修正。

---

## 0. 先说结论

**cdymm.com 应该做成「AI 原生画布工作台」，而不是「AI API 中转站」。**

现在的处境可以概括为一句话：

> **壳（叙事）已经跑到了画布工作台的位置，但里（能力）还停在 API 中转站。**

这不是批评，这是**已经付出的成本变成了沉没风险**——你花了大量工程把画布 fork 进来、做 SSO、做 go:embed 部署管线、做同域路由，这些都是为了"画布工作台"这个形态准备的。但如果能力不跟上，这些投入不会自动兑现。

所以整个规划的主轴只有一个：

> **在 3 个月内，把叙事里已经对外承诺的能力真实兑现。**

### 1.1 已经建成的资产

| 层 | 资产 | 状态 |
|---|---|---|

| 内核 | **TaskPlugin 协议**（接推理层零 Go 改动） | 上游已具备，**尚未启用** |

| 前端 | 画廊首页（标题/Logo/配色后台可配、i18n） | 可用 |

### 1.2 ⚠️ 未兑现的部分（必须在规划里直面）

| 首页宣称 | 实录 | 处理建议 |
|---|---|---|
| `announcement: 'Canvas Agent is live: say one sentence, the canvas builds itself'` | **无实现**。画布仓 `grep agent` 零命中，Go 侧零命中，此前「画布 Agent 即将上线」占位页已删除 | **先改文案**，别挂着 live |
| `agent.titleLine2: 'The Agent builds the canvas.'` | 同上 | 同上 |
| `studios` 里的 **Video studio「Text to video」** | 无在线生成入口，`/prompt-gallery` 只有静态作品 | 要么下线，要么尽快打通 |
| `hero.card.model: 'GPT Image 2.5'` | 依赖上游转发，不在我们控制内 | 标注为「coming from xxx」或换真实模型 |

**这条对策略的影响是决定性的**：

营销文案可以超前，但不能凭空。首页挂着 `is live` 而实际没有，会带来三个后果——
① 新用户点进来发现是假的，跳出率极高且不可逆；
② 老用户（已有 `yamomo` 这类种子账号）会失去信任；
③ 你自己会被自己写的文案锚定，往后每个决策都在追一个虚构的 deadline。

### 1.3 谁在做这件事（约束）

- **1 人 + AI 辅助** → 不能并行多条产品线
- **单容器 / 3000 端口 / 1Panel + 外部 PG** → 不适合重资产、不适合 K8s
- **无自持 GPU** → 一切生成依赖上游 API 或租卡
- **new-api 是 AGPLv3** → 我们对它的修改**必须开源**，仓库已公开满足

最后一条既是约束也是资产：**可以做「开源内核 + 商业增值」双轨**，但不能靠卖别人的授权赚钱。

## 2. 定位

### 2.1 一句话定位

> **cdymm.com —— AI 原生画布工作台。**
> 一句话描述想法，AI 在无限画布上把它编排成系列作品（图 / 视频 / 文案），并沉淀为可复用的工作流。

### 2.2 目标用户（必须收窄）

不是「所有想用 AI 的人」，而是：

> **需要批量产出视觉内容、并且内容之间有结构关系的人。**

三个最具体的画像：

| 画像 | 痛点 | cdymm.com 的解法 |
|---|---|---|
| **电商 / 独立站设计师** | 一个 SKU 要出主图、细节图、场景图、短视频封面，来回切工具、提示词散落各处 | 一张画布放参考图 + 提示词 + 成品，一键批量出套图 |
| **自媒体 / 内容创作者** | 封面、正文、封面视频、标题变体要保持一致调性 | 画布保持「风格锚点」，其余围绕它生成 |
| **小工作室 / 独立开发者** | 有想法但不会 ComfyUI 节点，也雇不起设计师 | Agent 把想法翻译成节点流，人来微调而不是从零搭 |

**为什么是这三个**：他们的内容天然是**一组**而不是**一张**。而"一组 vs 一张"正好是画布相对表单式工具的结构性优势。这也是唯一能把「画布」这个重投入兑现的场景。

### 2.3 差异化：**比编排，不比模型**

这是整个定位的判断核心。

```
别人的战场（模型层）：谁模型多、谁便宜、谁延迟低
  └── 我们没有 GPU，没有厂商关系，打不赢，也不需要赢

我们的战场（编排层）：谁能让用户少动手
  └── liblib 不会做（它是商城 + ComfyUI 节点编辑）
  └── bitahub 不会做（它是裸 OpenAI 兼容网关）
  └── zzai 不会做（它是模型报价引流站）
```

**核心价值主张（CVP）**：
> 别人的「生成」是**一次调用**；我们的「生成」是**一次编排**——把参考、提示词、产出之间的关系留在画布上，让它可复用。

### 2.4 明确的「不做什么」

取舍比选择更重要。以下四条建议**明确放弃**：

| 不做 | 理由 |
|---|---|
| ❌ 不买 GPU 自建算力集群 | 单人不具备多卡运维能力；对比阿里云/腾讯云按量计费无成本优势；把轻资产优势主动丢掉 |
| ❌ 不做通用「模型广场 / 比价站」 | zzai 已经占据这个心智；毛利极薄（实测对标站真实加价仅 0.33–1.18×），不值得 |
| ❌ 不卖「sk- 密钥 + 元/M tokens」 | **合规风险最高的一类形态**：上游厂商条款普遍禁止转授；bitahub 能做是因为它是中科类脑、有 5000P 自有集群、大概率带厂商合作前提 |
| ❌ 不做多人实时协同画布 | 这是最大的工程陷阱（CRDT/OT + WebSocket + 冲突解决），单人做不出竞争力，留给 P3 以后 |

## 3. 商业模式（三层）

```
L1  免费额度 + 按量付费        ← 现在就有，负责拉新与留存
L2  会员 + 算力包              ← 最大缺口，负责现金流（liblib 的 VipSku / PowerDetail 对应物）
L3  团队席位 / 私有渠道          ← 远期，负责客单价
```

**对外计量口径必须是「算力点 / 张 / 秒」，绝不出现 token 单价。** 这既是定位需要，也是合规刚需。new-api 内部 quota 保持原样，只在展示层换算。

### 一个容易被忽视的点：AGPL 与 MIT 的分界（双轨）

- **开源**：new-api 二开部分（必须，AGPLv3 合规）
- **可闭源 / 收费**：画布的前端 theme、预设工作流包、上层编排服务、行业 know-how

画布 fork 是 **MIT**（`basketikun/infinite-canvas`），**不受 AGPL 传染**，这是很好却被忽视的一点：我们可以把商业价值放在画布侧，把内核留给 AGPL。

## 4. 路线图（四个阶段）

每个阶段都有**退出判据**——如果判据不达标，应该做的是掉头，而不是加预算。

### P0 · 认账（1 周）

**目标：停止对外宣称不存在的东西。**

- [ ] 改首页文案：`Canvas Agent is live` → 换成真实上线的能力（或明确写 `Beta` / `Coming soon`）
- [ ] Video studio 要么下线要么挂「即将上线」，不要让 CTA 跳到静态画廊
- [ ] `hero.card.model` 换成真实可生成的模型名
- [ ] 建立**「首页宣称 → 实际可用性」对照清单**，作为每次发版的闸门

**判据**：首页每一句宣称都对应一个真实可点的功能。做不到就改文案，不许挂着。

> 这一步看着是退让，其实是整个规划的地基。**先让叙事诚实，后面的追赶才有方向。**

### P1 · 打通第一张图（3–4 周）

**目标：从「能看」变成「能用」。**

- [ ] 写 **ComfyUI TaskPlugin**（JS，零 Go 改动）——`buildSubmitRequest` → `POST /prompt`，`buildQueryRequest` → 轮询 `/history/{id}`
  - 没有自有 GPU 时，先用云 GPU 按小时租一台验证，跑通再谈长期
- [ ] 图片产物走已有对象存储模块（OSS/七牛/S3 已就绪）
- [ ] 生成入口落在**画布内**（右键节点 → 生成），而不是独立表单页
- [ ] **算力点计量**：对外显示「2 算力点 / 张」，内部换算 quota

**判据**：一个真实用户，从空白画布到拿到一张可用的图，**不超过 3 次点击**。
如果做不到，说明编排层的价值主张不成立，需要回头重定位。

### P2 · Canvas Agent MVP（6–8 周）

**目标：兑现定位。这是与所有竞品拉开差距的唯一机会。**

MVP 版本不要追求"全能"，做一个**窄而真**的版本：

- [ ] 输入框 → LLM 拆解为画布节点计划（首页现有的 `agent.plan` 数据结构已经躺在 schema 里，可直接复用）
- [ ] 只支持**固定 3–5 个预设类型**：主体图 / 风格迁移 / 局部重绘 / 视频延展
- [ ] 节点可以**手动修改**——Agent 的产物必须可编辑，否则用户会觉得自己被夺了控制权
- [ ] 每次生成结算一次（继续用记账内核）

**判据**：用户一句话能出**一组**内容（≥3 张有结构关系的图），而不是一张好图。
这是与 Midjourney / liblib 的分水岭——它们出「一张好看的图」，我们出「一套能用的图」。

### P3 · 商业化（8–12 周）

- [ ] 会员 SKU + 算力包 + 兑换码（`VipSku` / `PowerDetail` / `MembershipRedeemModal` 的对应物）
- [ ] workflow 市场 + **节点缺失检测**（对齐 liblib `comfyGetNotExistsNodes`）
- [ ] 作品分享链接（把画布变成传播载体——这是拉新的自然渠道）
- [ ] 团队席位（L3）

**判据**：有付费用户，且有≥30% 的周活在画布里产出过≥1 件作品。

## 5. 风险与合规（不可跳过）

| 项 | 要求 | 状态 |
|---|---|---|
| 增值电信业务经营许可证 | 川B2-20231491 | ✅ 已持有 |
| 《生成式人工智能服务管理暂行办法》 | 面向公众需备案 + 合规评估 | ⚠️ 生图生视频前必须办 |
| 《人工智能生成合成内容标识办法》（2025-09-01 施行） | 生成结果必须加**显式 + 隐式**双标识 | ⚠️ 未做，P1 必须带上 |
| 模型开源协议逐个核对 | SDXL/SD1.5 = OpenRAIL++-M（可商用有约束）；**Flux.1-dev = 非商用，不能卖**；Flux.1-schnell / Qwen-Image = Apache 2.0 | ⚠️ 每次新增模型都要查 |
| AGPLv3 合规 | 对 new-api 的修改必须开源 | ✅ 仓库已公开 |
| 用户协议 | 需写明「购买的是服务使用权与生成结果，非底层模型 API 访问权」 | ⚠️ 待补 |

> 我是工程师不是律师。正式对外收费前，建议做一次法务审阅；厂商条款会变，需要定期复核。

## 6. 需要你拍板的四个决策

规划里所有内容都依赖这四个前提，建议先确定再动手：

1. **算力从哪来？** —— 云 GPU 按小时租（轻资产、成本高、适合验证） / 上游 API 转发（成本低、无差异化、合规要注意） / 长期租卡（折中）
   → 影响 P1 的实现方式与整个成本结构
2. **是否接受先改文案承认没做完？** —— 这是 P0 的全部内容，投入 1 周但不产生任何新功能
3. **三人画像选哪一个先打？** —— 建议**电商/设计师**，因为套图需求最刚、付费意愿最明确
4. **是否走「开源内核 + 商业增值」双轨？** —— 需要把商业价值有意放在**画布侧（MIT）**而不是 new-api 侧（AGPL）

## 附：为什么不建议走 bitahub / liblib 的路

| | bitahub | liblib | **cdymm.com 建议** |
|---|---|---|---|
| 形态 | 裸 OpenAI 兼容网关 | 模型商城 + 工作流社区 | **AI 画布工作台** |
| 壁垒 | 自有 GPU 集群 5000P | 社区内容积累 + 品牌 | **编排层交互** |
| 我们能不能抄 | ❌ 无 GPU、无厂商关系 | ❌ 社区冷启动需要几年 | ✅ 画布已建成、垂直场景空着 |
| 合规风险 | 高（明码 token 单价 + 自持密钥） | 中 | 低（不暴露 API、不宣称 token 价） |

**一句话**：不要去抢别人已经站稳的位置，要去占一个他们结构性的弯腰成本高、而我们正好已经站在旁边的位置。画布工作台就是那个位置。
