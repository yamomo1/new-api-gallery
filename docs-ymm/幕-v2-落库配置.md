## 1. 直接能贴的 JSON

### 1.1 文本模型倍率（`ModelRatio`）

```json
{
  "ymm-tx-s": 0.075,
  "ymm-tx-m": 1.25,
  "ymm-tx-l": 7.875
}
```

**怎么算出来的**：`倍率 = 上游输入价(USD/1M) ÷ 2`
因为 `ModelRatio = 1` 等价于 `1 quota / token`，而 `1 quota = $0.000002`，
所以 `$2/1M token ⇔ 倍率 1`。`ymm-tx-l` 额外乘了 1.05 的模型加价。

### 1.2 文本输出倍率（`CompletionRatio`）

```json
{
  "ymm-tx-s": 4.0,
  "ymm-tx-m": 4.0,
  "ymm-tx-l": 4.0
}
```

三个模型输出价都是输入价的 4 倍（0.60/0.15、10/2.5、60/15），所以统一 4.0。

### 1.3 图片 / 视频按次价（`ModelPrice`，单位 **USD/次**）

```json
{
  "ymm-img-s-1k": 0.01,
  "ymm-img-s-15k": 0.02,
  "ymm-img-s-2k": 0.035,
  "ymm-img-m-1k": 0.02,
  "ymm-img-m-15k": 0.04,
  "ymm-img-m-2k": 0.07,
  "ymm-img-l-1k": 0.04,
  "ymm-img-l-15k": 0.08,
  "ymm-img-l-2k": 0.14,
  "ymm-vid-25-480p-5s": 0.460274,
  "ymm-vid-25-720p-5s": 1.035616,
  "ymm-vid-25-1080p-5s": 2.563014,
  "ymm-vid-25-480p-10s-in": 1.105479,
  "ymm-vid-25-720p-10s-in": 2.484932,
  "ymm-vid-25-1080p-10s-in": 6.124658
}
```

**关键点：尺寸/分辨率不能做参数，必须拆成独立模型名。**
`ModelPrice` 是「每个模型一个固定价」，无法按请求里的 size 变量计价。
所以 `ymm-img-m-2k`、`ymm-img-m-15k`、`ymm-img-m-1k` 是**三个模型**，
前端选 2K 就请求 `ymm-img-m-2k`。视频同理（秒数也是只有 5s 一档，符合「不开放自定义时长」）。

**视频价怎么来的**：`单次总成本(¥) ÷ 7.3`
例：`7.56 ÷ 7.3 = 1.035616 USD`（Seedance 2.5 720P 5s，官方价 1.512 元/秒 × 5s）。
含输入的档位（如 `ymm-vid-25-720p-10s-in`）直接用整单成本 `18.14 ÷ 7.3 = 2.484932`，
因为输入 10s 也计费，不能按输出秒数摊。

### 1.4 充值档位

`amount_options`（金额选项）：

```json
[10, 30, 50, 100, 300, 500, 1000]
```

`amount_discount`（金额折扣 = `1 / (1+赠送比例)`，因为本系统折扣作用于**实付金额**）：

```json
{
  "50": 0.9804,
  "100": 0.9709,
  "300": 0.9615,
  "500": 0.9524,
  "1000": 0.9434
}
```

> 语义换算：送 6% 幕 ≡ 收 94.34% 的钱，所以 `1000 → 0.9434`。
> 10 / 30 档不送，**不要写进 map**（写 `1.0` 也行，但有些版本会当成"有折扣"显示角标）。
>
> **两种实现方式，选一个：**
>
> | | 方案 A：折扣（推荐，零额外代码） | 方案 B：送幕（与文档字面一致） |
> |---|---|---|
> | 后台配 | `amount_discount` 如上的表 | `amount_discount` 留空 |
> | 代码 | 不用改 | `getTopUpQuota` 里加赠送表 |
> | 用户看到 | 「充 1000 限时 94 折，实付 ¥943.40」 | 「充 1000 送 6000，到账 106,000 幕」 |
> | 经济效果 | 单价 0.009434 元/幕 | 单价 0.009434 元/幕 | 
>
> 两者**单位价格完全等价**，只是文案不同。A 少写代码，B 更像行业惯例（用户对"送"更敏感）。

### 1.5 会员分组倍率

```json
{ "vip": 0.89 }
```

配合「分组定价」里把 `UserUsableGroups` 加上 `vip`，用户开通会员时由订阅流程把他切到 `vip` 组。

## 2. 批量写入（不手填的话用这个）

18 个 SKU 手填很烦，用接口一次性写。打开后台任意页面，F12 → Console：

```js
// 1) 从 DevTools 的 Network 里随便点一个 /api/ 请求，复制 Authorization 头的 Bearer 值
const AUTH = 'Bearer eyJhbGciOi...';   // ← 换掉

const opts = {
  "ModelRatio":      { "ymm-tx-s": 0.075, "ymm-tx-m": 1.25, "ymm-tx-l": 7.875 },
  "CompletionRatio": { "ymm-tx-s": 4.0, "ymm-tx-m": 4.0, "ymm-tx-l": 4.0 },
  "ModelPrice":      { "ymm-img-s-1k": 0.01, "ymm-img-s-15k": 0.02, "ymm-img-s-2k": 0.035,
                       "ymm-img-m-1k": 0.02, "ymm-img-m-15k": 0.04, "ymm-img-m-2k": 0.07,
                       "ymm-img-l-1k": 0.04, "ymm-img-l-15k": 0.08, "ymm-img-l-2k": 0.14,
                       "ymm-vid-25-480p-5s": 0.460274, "ymm-vid-25-720p-5s": 1.035616, "ymm-vid-25-1080p-5s": 2.563014, "ymm-vid-25-480p-10s-in": 1.105479, "ymm-vid-25-720p-10s-in": 2.484932, "ymm-vid-25-1080p-10s-in": 6.124658 },
  "GroupRatio":      { "vip": 0.89 },
  "QuotaPerUnit":    500000,
  "USDExchangeRate": 7.3,
  "Price":           1,
  "payment_setting.amount_options":  "[10,30,50,100,300,500,1000]",
  "payment_setting.amount_discount": '{"50":0.9804,"100":0.9709,"300":0.9615,"500":0.9524,"1000":0.9434}',
};

for (const [key, value] of Object.entries(opts)) {
  const body = { key, value: typeof value === 'object' ? JSON.stringify(value) : value };
  const r = await fetch('/api/option/', {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json', Authorization: AUTH },
    body: JSON.stringify(body),
  }).then(x => x.json());
  console.log(r.success ? '✅' : '❌', key, r.success ? '' : r.message);
}
```

`ModelRatio` / `CompletionRatio` / `ModelPrice` 是 **整体替换**（不是合并），
所以脚本里要写全量；如果你已有其它模型的定价，先把它们并进来再写。

## 3. 必须改代码的 3 处（配置解决不了）

这三处不是"粘贴"，是改文件。**不改的话，钱和幕对不上。**

### 3.1 加常量：1 幕 = 513 quota

```go
// common/constants.go 附近
const MuPerQuota = 5136       // 1 幕 = 5,136 quota（K = 500000/5136 = 97.35 幕/USD）
const MuPerRMB   = 10         // 1 元 = 10 幕（1 幕 = ¥0.10）
```

### 3.2 充值发幕口径（**最关键，不改会多送 33.5%**）

现状：`controller/topup.go` 的 `getTopUpQuota` 用的是

```go
quota = amount × common.QuotaPerUnit      // 1 额度单位 = 500,000 quota = $1
```

但本系统里「1 元人民币」应该给 `10 幕 = 51,360 quota`，而不是 `500,000 quota`（那是 $1 的量）。

**不改会出现两种错法，都很致命：**

| 配置状态 | 充 10 元到账 | 相对正确值 |
|---|---:|---:|
| ✅ 改代码 + `Price=1` | **100 幕** | 正确 |
| ❌ `Price=1` 但 quota 仍 ×500000 | 975 幕 | 多送 **9.7 倍** |
| ❌ `Price=7.3`（amount 当美元额度） | 133 幕 | 多送 **33.5%** |

```go
// controller/topup.go  getTopUpQuota()
- quota = quota.Mul(decimal.NewFromFloat(common.QuotaPerUnit))
+ // 幕本位：金额(元) → 幕 → quota
+ quota = quota.Mul(decimal.NewFromInt(common.MuPerRMB * common.MuPerQuota))  // ×51,360
```

改完 `Price` 必须设为 **1**（1 元额度卖 1 元），否则 `getPayMoney` 还会乘 7.3 变成收 730 元。

> 为什么不能靠 `QuotaPerUnit=51300` 蒙过去：模型计费路径的 `quota = tokens × ModelRatio`
> 与 `QuotaPerUnit` 无关，改它只会让「充 1 元得多少」和「调一次模型扣多少」互相打架。

### 3.3 前端展示：quota → 幕

```ts
// 建议放在 features/wallet/lib/ 下
export const MU_PER_QUOTA = 5136
export const quotaToMu = (quota: number) => Math.floor(quota / MU_PER_QUOTA)
export const muToYuan = (mu: number) => mu * 0.10
```

需要替换展示口径的位置：
- 钱包页余额（`features/wallet/components/wallet-stats-card.tsx`）
- 充值页金额/到账提示（`recharge-form-card.tsx`）
- 用量日志的「额度」列（`features/usage-logs`）
- 模型广场的价格展示（如有）

## 4. 落库后逐项验收

按顺序点一遍，任何一步对不上就停：

| # | 操作 | 期望 |
|---|---|---|
| 1 | 后台模型定价看到 18 个 `ymm-*` 模型（3 文本 + 9 图片 + 6 视频） | 倍率/按次价与 §1 一致 |
| 2 | 钱包页充 10 元 | 到账 **100 幕**（若是 975 幕 → §3.2 没改；若是 133 幕 → `Price` 还是 7.3） |
| 3 | 生成一张 `ymm-img-m-2k` | 扣 **7.0 幕**（理论 6.81，取整到 0.5 档 → 7.0） |
| 4 | 生成一条 `ymm-vid-25-720p-5s` | 扣 **102 幕**（¥10.20；若还是 134 幕 → 视频价目没更新） |
| 5 | 调一次 `ymm-tx-m`（in 800 / out 600） | 扣 **0.8 幕** |
| 6 | 选 1000 档 | 方案 A：实付 ¥943.40、到账 10,000 幕；方案 B：实付 ¥1,000、到账 10,600 幕（含 6% 赠送） |
| 7 | VIP 用户生成同一张 2K 图 | 扣 **6.3 幕**（7.0 × 0.89 向上取整到 0.1） |
| 8 | 后台「账单」核对一单 | `实付金额 / 幕数 ≈ 0.094~0.10`，毛利用 `幕 × 0.10 - 成本` 复核在 25%~27% |

第 2 步是最容易错的：如果到账 1,335 幕，说明 §3.2 没改（还在用 `QuotaPerUnit`）；
如果到账 6,849 幕，说明 `Price` 还是 7.3。
