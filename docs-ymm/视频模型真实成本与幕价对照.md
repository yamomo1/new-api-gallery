## 2. 反解官方计费公式（六项数字全部吻合）

```
视频费用 = Token单价 × Token用量
Token用量 = (输出宽 × 输出高 × 输出帧率 × 输出时长) / 1024           [不含视频输入]
Token用量 = (输出宽 × 输出高 × 输出帧率 × (输入时长+输出时长)) / 1024  [包含视频输入]
```

**由 token 用量反解出两个隐藏参数：**

| 分辨率 | 反解 W×H | 实际像素 | 验证 |
|---|---:|---|---|
| 480P | 409,920 | **854 × 480** | 854×480×24×5/1024 = 48,037.5 ✅ |
| 720P | 921,600 | 1280 × 720 | 1280×720×24×5/1024 = 108,000 ✅ |
| 1080P | 2,073,600 | 1920 × 1080 | 1920×1080×24×5/1024 = 243,000 ✅ |

**帧率 = 24fps**（不是 30 或 25；用 5s / 24fps 代入三档全部精确命中）。

> 注意 480P 是 **854×480**（16:9 标准值），不是常见的 864×480 —— 差 1.2%，
> 但乘以 120 帧后 token 差 576，跟官方 48,037.5 对不上。这个细节决定成本能不能算准。

## 3. 成本基线

| 分辨率 | 纯生 5s | 元/秒 | 含输入 10s | 元/秒 | 含输入/纯生 |
|---|---:|---:|---:|---:|---:|
| 480P | ¥3.36 | 0.672 | ¥8.07 | 0.807 | 1.20x |
| 720P | ¥7.56 | 1.512 | ¥18.14 | 1.814 | 1.20x |
| 1080P | ¥18.71 | 3.742 | ¥44.71 | 4.471 | 1.19x |

**分辨率的成本杠杆：**

- 480P → 720P：**2.25 倍**（像素 409,920 → 921,600）
- 720P → 1080P：**2.47 倍**（921,600 → 2,073,600）
- 480P → 1080P：**5.57 倍**

基本等于像素比（2.25 / 2.25 / 5.06）—— **成本随像素线性走**，
所以分辨率档位不能拍脑袋，必须按像素差定价。

**含输入为什么只贵 1.2 倍而不是 2 倍？**
单价从 70 降到 42（−40%），但计费时长从 5s 翻到 20s（+300%），相乘 ≈ 1.2 倍。
**这是官方的定价引导：鼓励图生视频 / 延长视频，因为输入侧算力便宜。**

## 8. 三个上线前的必查项

1. **确认 24fps 是否为客户侧实际帧率**。若上游按 30fps 出片，token 多 25%，成本同涨 25%。
2. **确认「样片 / 预览」是否单独计费**。对标站有「样片模式」，我们若有预览生成，
   要么复用纯生价，要么单列低价档。
3. **按秒线性外推**。`tokens` 与秒数严格线性（公式里就是乘时长），
   所以 10s 纯生 = 5s × 2 = **¥6.72 → 90 幕**，无需重新议价。

## 附：换算公式速查

```
tokens = 宽 × 高 × 24 × 时长 / 1024
费用¥  = tokens × 单价 / 1,000,000
纯生单价：480P/720P = 70，1080P = 77
含输入单价：480P/720P = 42，1080P = 46（计费时长 = 输入 + 输出）

幕 = 费用¥ × 13.34          → 挂牌（<20 取 0.5 / 20–100 取 1 / >100 取 2）
实付¥ = 幕 × 0.10
```
