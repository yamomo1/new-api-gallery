## 1. 为什么不能直接把 tokens.css 丢进去

先做了变量对比，`design-system/tokens.css` 的 `:root` 与站点 `global.css` 有
**14 个同名但取值不同**的变量：

| 变量 | 站点现值 | 设计系统值 | 冲突后果 |
|---|---|---|---|
| `--primary` | `#935b00` 琥珀金 | `#5b5bd6` 墨靛蓝 | **全站主色一夜变色** |
| `--background` | `#f9f8f5` 暖纸米白 | `#ffffff` 纯白 | 整体调性从暖转冷 |
| `--foreground` | `#0b0d11` | `#18181b` | 文字对比度变化 |
| `--card` / `--card-2` | 米白系 | 纯白 / 灰 | 卡片层次重排 |
| `--border` / `--border-strong` | 暖灰 | 中性灰 | 描边冷暖变化 |
| `--muted` | `#6a6f76` | `#71717a` | 次要文字 |
| `--radius` | `1rem` | `10px` | 圆角差 6px |
| `--shadow` | 深绿调 | 中性黑调 | 阴影冷暖 |
| `--glow` | 固定 rgba | `var(--primary-soft)` | 派生关系变化 |
| `--font-sans` / `--font-serif` | 含苹方/雅黑 | 纯开源栈 | 中文渲染略变 |

直接覆盖 = 未经确认的整体改版。所以做成**隔离 + 开关**（见 §3）。

好消息：**`.ymm-*` 组件类与站点 215 个类名零冲突**，只有 `.dark` / `.on` 同名且
本来就该共用。这让「增量叠加」完全可行。

## 2. 为什么是同步脚本，而不是 import 外部文件

Docker 构建上下文是 `gallery-frontend/` 本身（`docker-compose.yml` → `build.context: .`），
**`../design-system/` 不在上下文里**，容器内 `npm run build` 拿不到外部目录。

所以选了：

```
design-system/tokens.css      ← 唯一真源（改这里）
        │  scripts/sync-design-system.mjs
        ▼
src/styles/ymm-tokens.css     ← 生成物，勿手工编辑
        │  main.tsx import
        ▼
     打包进 dist
```

并且把同步挂进了 npm hooks，**让它不可能被忘记**：

```json
"sync:design":  "node scripts/sync-design-system.mjs",
"check:design": "node scripts/sync-design-system.mjs --check",
"dev":          "npm run sync:design && rsbuild dev",
"build":        "npm run sync:design && rsbuild build"
```

`build` / `dev` 每次自动同步；CI 可用 `check:design` 卡不同步。

> 这不是又一份双份维护：生成物是**单向**的，且脚本会告诉你它自己是生成物。

## 3. 脚本生成时做了三件事

1. **剔除 14 个冲突变量** → 不放进 `:root`，改塞进 `html.ymm-look` 开关层。
   47 个**新增**令牌（`--space-*`、`--text-*`、`--dur`、`--ease`、`--primary-grad`、
   `--radius-sm/lg/xl`、`--success/danger/warning`、`--nav-h` 等）全部保留。
2. **追加站点桥接层** —— 这是最容易漏的一步：

   `global.css` 实际被引用的别名是 `--accent`(10 处) / `--gold`(10) / `--lime`(4) /
   `--lime-bright`(3) / `--gold-soft`(2)，而设计系统的预设只定义 `--primary` 系列。
   不桥接就会出现「选了樱花粉，按钮还是金色」这种半吊子状态。用一条属性选择器解决：

   ```css
   html[class*="accent-"] {
     --accent: var(--primary);
     --lime: var(--primary);
     --lime-bright: var(--primary-hover, var(--primary));
     --gold: var(--primary);
     --gold-soft: var(--primary-soft);
     --cursor-glow-color: color-mix(in srgb, var(--primary) 30%, transparent);
   }
   ```
   12 套预设共用这一份映射，加新预设无需重复劳动。

3. **其余原样保留**：12 套 accent 预设（24 条规则，含黑白双值 + 渐变）、9 个
   `@keyframes`、26 个 `.ymm-*` 组件类。

## 4. 怎么启用新版 UI（开关）

现在站点**看不出任何变化**——这是故意的。

想整体切到设计系统的中性白 / 近黑 + 墨靛蓝基线：

```ts
document.documentElement.classList.add('ymm-look');
```

或在 Vorf 里临时 kiểm。不需要时删掉 `html.ymm-look{...}` 那一块即可，零残留。

建议用法：在一个测试环境加 `ymm-look`，对比后再决定是否设为默认。

## 6. 顺手修掉的一个线上 bug：Google Fonts 白屏

`index.html` 原先有：

```html
<link href="https://fonts.googleapis.com/css2?family=Lora...&family=Public+Sans..." rel="stylesheet">
```

`<link rel="stylesheet">` 是**阻塞渲染**资源，而 `fonts.googleapis.com` 在国内基本不可达——
浏览器要一直等到连接超时才开始绘制，**期间整屏全白**。

讽刺的是 `global.css` 里本来就有自托管的 `@font-face`（`src/styles/fonts/*.woff2`，
Public Sans + Lora，SIL OFL 可商用），那个外链**完全多余**。已移除。

这和之前修 `home-v2.html` / `detail-v2.html` 白屏是同一个根因，记进苹果：

> **铁律：设计系统与站点页面都不允许有阻塞渲染的外网依赖。**
> 确需品牌字体就放自家域名 + `font-display: swap`。

## 7. 两个必须知道的坑（代码里已处理）

### 7.1 inline style 优先级高于 CSS class

一旦往 `<html style>` 写过 `--primary`，`html.accent-sakura{--primary:...}` 就**永远赢不了**。
所以两种模式切换时必须清理对方：`applyPreset()` 先 `clearInline()`，`applyAccent()` 先
`clearPresetClass()`。不清理会出现「主色是新的、渐变是旧的」的混合态。

### 7.2 MutationObserver 自触发死循环

`ThemeApplier` 要监听 `<html>` 的 class 变化（深浅切换时重新应用），但 `applyPreset`
本身会改 class → 反过来触发自己 → 无限循环。

解法是 `applyPreset` 的**幂等短路**：目标 class 已挂好且无 inline 残留时直接 `return`，
不碰 DOM，自然不再触发观察者。这个短路不能删。

## 8. 怎么用（给二次开发）

**换配色**：站点 Nav 右侧调色盘，12 套点一下即可，选择写进
`localStorage['zz-accent-preset']`。后台 `site.theme.accent` 配任意 hex 仍走自定义模式。

**用动效**（在任何 `.tsx` 上加 class 即可）：

| class | 效果 |
|---|---|
| `ymm-reveal` | 滚动进入视口时上浮淡入（可 `data-d="1..4"` 错峰） |
| `ymm-btn-glow` | 按钮流光 + 辉光 hover |
| `ymm-card-rise` | 卡片抬升 + 顶部强调线 |
| `ymm-shimmer-text` | 标题流光扫过 |
| `ymm-shimmer-bg` | 骨架屏微光 |
| `ymm-spotlight` | 卡片指针聚光（需配套 JS 写 `--mx/--my`） |
| `ymm-cursor-glow` | 全局跟随光晕（需配套 JS 写 transform） |
| `ymm-glass` / `ymm-glass-menu` | 磨砂玻璃面板 / 菜单 |
| `ymm-dd` / `ymm-dd-menu` / `ymm-dd-item` | 自定义下拉 |
| `ymm-slider` | 方角凹槽滑块 + 常驻流光条 |
| `ymm-wf-card` / `ymm-wf-collapse` | 瀑布流卡片 + 悬停推挤展开 |
| `ymm-wbtn` | 站点风格的渐变按钮 |

配套 JS 在 `design-system/home-v2.html` 的 `<script>` 里，搬的时候注意挑loxacin kh （cedure、Spotlight 需要指针坐标）。

**用令牌**：`var(--space-6)`（24px）、`var(--text-base)`（14px）、
`var(--dur)` / `var(--dur-fast)`、`var(--ease)` / `var(--ease-out)`、
`var(--radius-sm|lg|xl)`、`var(--shadow-sm|lg)`、`var(--primary-grad)`（渐变底）。
