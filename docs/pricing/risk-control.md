# 风控推荐配置（自动禁用 / 自动重试 / 限流）

> 配套文档：[README.md](./README.md)（定价部分）
> 配置入口：后台 → 系统设置 → 运营设置 / 账单，或直接改 options。

目标只有三个：**坏渠道自动下线**、**用户刷限额别烧穿你的成本**、**上游抖动时自动重试而不是报错给用户**。

---

## 一、渠道自动禁用（最重要）

| 配置项 | 推荐值 | 说明 |
|---|---|---|
| `AutomaticDisableChannelEnabled` | **true** | 主开关。默认 `false`（`common/constants.go:134`），务必打开 |
| `AutomaticDisableStatusCodes` | `401,403,429` | **当前默认只有 `401`**（`operation_setting/status_code_ranges.go:17`）。加上 `403`（密钥失效/被封）和 `429`（欠费或限流）能在第一时间止损 |
| `AutomaticEnableChannelEnabled` | **true**（保守可 false） | 恢复后自动上线。开了省人工；如果你更在意稳定，保持 false 手动恢复 |
| `AutomaticRetryStatusCodes` | `429,500-599` | 配合自动重试；同时amis务必保留兜底的上游多通道切换 |

**为什么 429 要禁用**：429 通常意味着这个 key 欠费/被限。继续让它接量，用户只会看到一堆失败请求，而你还得为重试买单。

## 二、限流（防羊毛党 Defaults）

| 层 | 配置项 | 推荐值 | 说明 |
|---|---|---|---|
| 全局 API | `GlobalApiRateLimitNum` / `...Duration` | 依用户量定，建议先放宽到 QPS 200 / 60s | 保护整机 |
| 全局 Web | `GlobalWebRateLimitNum` / `...Duration` | QPS 60 / 60s | 防止 Web 端被刷接口 |
| 注册/登录 | 失败次数限制 | 保持开启 | 防爆破 |
| 模型维度 | `ModelRequestRateLimitGroup` | 给**高价模型单独分组**限流 | 例如 Opus/Sol 级单独限，免费用户请求被拦截而不是被放行 |

**用户级三件套**（用户管理 → 编辑用户）：
- 设置每个用户的 **总可用额度**，超出即拦截
- 给免费用户设置 **每日消耗上限**
- 新注册用户默认给小额体验额度，**不给无限额度**

> 羊毛党的典型行为是：拿到 tokens 就批量灌超长上下文。额度上限 + 每日上限这两道闸门缺一不可。

## 三、省钱的三个 placebo-free 手段

| 手段 | 做法 | 效果 |
|---|---|---|
| Prompt 缓存 | 系统提示词固定、长 system prompt 前置；`CacheRatio` 设成小于 1 的折扣 | 命中后输入成本打骨折，见效最快 |
| 渠道权重 | 便宜/稳定的渠道权重调高，贵的当兜底 | 单位成本直接下降 |
| 低价模型兜底 | 免费档只开放经济层模型（渠道分组隔离） | 免费用户的成本几乎可以忽略 |
| 单用户 max_tokens 限制 | 在用户/令牌层限制 | 防止一次回答吃掉一天毛利 |

## 四、日常巡检清单

每天花两分钟看这几个：

1. `/profit` 看板：有无**负毛利**的模型（红字行）
2. 渠道列表：有无线上 `自动禁用` 状态的渠道（说明上游出问题了）
3. 用户消耗排行：有没有异常爆量的新账号
4. 日志页筛 `type=错误`：集中在某个模型/渠道就说明该换供应商了

---

## 五、接入后的验证方式

改完全局开关后按顺序验一遍：

```bash
# 1) 把某个渠道的密钥故意改错，发一次请求
#    期望：渠道被自动禁用，不再有用户请求打到它
# 2) 恢复正确密钥
#    期望：AutomaticEnableChannelEnabled=true 时自动恢复；否则手动启用
# 3) 连续快速发 100 次请求（用无效 token）
#    期望：触发全局限流，返回明确限流错误而不是 500
```

上线前建议先在**非默认分组**的渠道上验证一遍，确认行为符合预期再全量放开。
